# Промпт для создания презентации проекта Progressusbot

## Контекст
Создай презентацию для программистов о Telegram-боте Progressusbot - MVP для личного развития. Презентация должна быть послайдово с текстом, фокус на архитектуре решения.

## Информация о проекте

### Описание проекта
Progressusbot - Telegram-бот для личного развития по трём направлениям: заработок, здоровье, ментальное состояние. Бот использует GPT-4o-mini через OpenRouter API для персонализации и генерации контента.

### Технологический стек
- **Backend Framework**: Python 3.12, aiogram 3.13.1 (async Telegram Bot API)
- **Web Server**: FastAPI 0.115.0 (webhook сервер)
- **Database**: PostgreSQL 16 с asyncpg драйвером
- **Cache/FSM Storage**: Redis 7.4 (FSM storage и Celery broker)
- **AI Integration**: OpenRouter API (GPT-4o-mini)
- **Background Tasks**: Celery 5.4.0
- **Deployment**: Docker Compose
- **ORM**: SQLAlchemy (async)

### Архитектура решения

#### Слоистая архитектура (Layered Architecture)
1. **Handlers Layer** (`app/handlers/`)
   - Обработчики команд и сообщений от Telegram
   - Роутеры: start, survey, reports, payments, referral, restart, menu, privacy
   - Разделение ответственности по функциональным областям

2. **Services Layer** (`app/services/`)
   - Бизнес-логика приложения
   - user_service.py - работа с пользователями
   - referral_service.py - реферальная система
   - survey_state_service.py - сохранение/восстановление состояния опроса

3. **Models Layer** (`app/models.py`)
   - SQLAlchemy ORM модели
   - User, Survey, Report, Payment
   - Relationships между сущностями

4. **GPT Integration Layer** (`app/gpt.py`)
   - Асинхронный клиент OpenRouter API
   - Функции генерации: вопросы, роадмап, ДЗ, оценка отчетов
   - Интеграция с системными промптами

5. **Prompts Layer** (`app/prompts/`)
   - Системные промпты для GPT
   - Промпты ролевых моделей (5 вариантов)
   - Промпты для анализа ДЗ

6. **Middleware Layer** (`app/middleware/`)
   - Rate limiting middleware

#### FSM (Finite State Machine) для управления workflow
- **Storage**: Redis через RedisStorage от aiogram
- **Состояния**: SurveyStates (privacy_consent, gender, age, name, values, development_spheres, detailed_questions, role_model, goal_3months, roadmap_generation, finish, consultation)
- **Восстановление состояния**: Сохранение состояния опроса в БД для восстановления после перезапуска

#### Асинхронная архитектура
- Полностью асинхронный код (async/await)
- Асинхронные операции с БД через asyncpg
- Асинхронные HTTP запросы к OpenRouter API
- Non-blocking I/O операции

#### База данных
- **PostgreSQL 16** с asyncpg драйвером
- **Модели данных**:
  - User: user_id, level (0-10), category, personality, roadmap, current_homework
  - Survey: basic_answers, detailed_answers, detailed_questions, role_model, goal_3months, roadmap
  - Report: report_text, gpt_feedback, level_before, level_after, is_approved, revision_required
  - Payment: payment_id, amount, status
- **Relationships**: User → Surveys, Reports, Payments (one-to-many)

#### Интеграция с GPT через OpenRouter
- **Функции генерации**:
  1. `generate_detailed_questions()` - 5 персонализированных вопросов на основе базовых ответов
  2. `generate_roadmap()` - роадмап достижения цели на 3 месяца (4 этапа)
  3. `generate_first_homework()` - первое ДЗ уровня 0
  4. `generate_next_homework()` - следующее ДЗ для нового уровня
  5. `evaluate_report_with_revision()` - оценка отчета и генерация правок/нового ДЗ
- **Ролевые модели**: 5 вариантов (Эндрю Тейт, Михаил Гребенюк, Хабиб, Олег Тиньков, Тайлер Дёрден)
- Каждая модель имеет свой системный промпт и стиль общения

#### Фоновые задачи (Celery)
- Celery worker для асинхронной обработки задач
- Redis как message broker
- Возможность вынесения тяжелых операций (генерация контента) в фоновые задачи

#### Деплой и инфраструктура
- **Docker Compose** для оркестрации контейнеров
- Контейнеры: bot (FastAPI), postgres, redis, celery-worker
- **Режимы работы**:
  - Polling режим (для разработки) - бот сам опрашивает Telegram
  - Webhook режим (для production) - Telegram отправляет обновления на endpoint
- Автоматическое создание таблиц БД при старте
- Миграции через Alembic

### Workflow пользователя
1. Приветствие → Согласие на обработку ПД
2. 5 базовых вопросов (пол, возраст, имя, ценности, сферы развития)
3. 5 развернутых вопросов от GPT (генерируются на основе базовых ответов)
4. Выбор ролевой модели (5 вариантов)
5. Ввод цели на 3 месяца
6. Генерация роадмапа с 4 этапами (недели 1-2, 3-4, 5-8, 9-12)
7. Получение первого ДЗ уровня 0
8. Цикл: Выполнение ДЗ → Отчет → Оценка GPT:
   - ✅ Хорошо → Новое ДЗ для следующего уровня
   - ⚠️ Плохо → Правки к текущему ДЗ с конкретными инструкциями

### Ключевые архитектурные решения
1. **Разделение на слои** - четкое разделение handlers/services/models
2. **FSM для управления состоянием** - Redis как хранилище состояний
3. **Асинхронность** - полная асинхронная архитектура для масштабируемости
4. **Персонализация через GPT** - динамическая генерация контента на основе ответов пользователя
5. **Ролевые модели** - разные стили общения через системные промпты
6. **Система уровней** - прогрессия от 0 до 10 уровня
7. **Умная проверка ДЗ** - GPT анализирует отчеты и дает обратную связь
8. **Восстановление состояния** - сохранение состояния опроса в БД для восстановления после перезапуска
